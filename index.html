Oh hai there!

This site was frankensteined together using ideas from the EE site and real-world examples from support tickets. It is meant to be a standalone package that anyone can download, add to their own git repo, and customize for their own purposes. The code here has been commented for ease of use/update/understanding. Check out About this site at the bottom left for a menu of features.

Guides: Modals & Banners

Regular modals

Top-layer modal

This one is a native <dialog> opened with showModal(). The browser puts it in the top layer, above everything on the page regardless of z-index, so it behaves differently from the regular modals when a guide tries to appear over it.

Guides: Duplicate DOM

The same element exists twice, but only one copy is visible at a time. Target the visible one, then press Switch and see if the guide follows.

A. Per-theme copies (display: none)

Both copies share the SAME id (dup-save-a), classes and text. Invalid HTML, but very common in the wild. The first one in the page is hidden.

About this site

        
This is a practice site for learning Pendo tagging and guides. Everything on it is fake: there is no real account, store or AI. Pick a page below to explore. I dare you to use the konami code somewhere.


        
        


        

          
Under the hood

          

            
    
              
  • Setup: paste your Pendo API key into assets/js/config.js. The domain you host the site on must also be allowed in your Pendo subscription.
    • 
              
  • Visitor identity: whoever "logs in" is sent to Pendo as the visitor (username) and account, with role and plan as metadata.
    • 
              
  • Light and dark mode: use the toggle in the top banner. Your choice is remembered.
    • 
              
  • Generating activity: use the Activity Simulator in this site, or the unattended runner in the automation folder (it can run on a schedule with GitHub Actions). Fake visitors are named sim-...@example.com so they are easy to filter out.
    • 
              
  • Adding things: new pages, scenarios and styles are explained in the project's README.md.
